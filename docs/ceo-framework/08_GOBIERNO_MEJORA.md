# Gobierno y Mejora Continua

## Objetivo

Mantener el agente útil, seguro y actualizado después del lanzamiento.

## 1. Dueños del sistema

| Área | Responsable | Responsabilidad |
| --- | --- | --- |
| Negocio |  | Define prioridades y resultados |
| Operación |  | Revisa casos y escalamiento |
| Tecnología |  | Mantiene integraciones |
| Contenido |  | Actualiza conocimiento |
| Dirección |  | Decide cambios mayores |

## 2. Cadencia de revisión

| Frecuencia | Actividad |
| --- | --- |
| Diaria al inicio | Revisar errores y escalaciones |
| Semanal | Revisar métricas y casos destacados |
| Mensual | Ajustar conocimiento, flujos y objetivos |
| Trimestral | Evaluar expansión a nuevos agentes |

## 3. Métricas de gobierno

- Conversaciones atendidas.
- Casos resueltos automáticamente.
- Casos escalados.
- Tiempo de respuesta.
- Errores críticos.
- Satisfacción.
- Conversión.
- Ahorro operativo estimado.

## 4. Gestión de cambios

Todo cambio relevante debe registrar:

- Qué se cambió.
- Por qué se cambió.
- Quién lo aprobó.
- Qué riesgo reduce o qué mejora busca.
- Cómo se probó.
- Fecha de publicación.

## 5. Actualización de conocimiento

La base de conocimiento debe revisarse cuando:

- Cambian precios, políticas o servicios.
- Aparecen preguntas frecuentes nuevas.
- El agente falla por falta de información.
- Cambia el proceso comercial u operativo.
- Se lanza una nueva campaña.

## 6. Auditoría

Revisar muestras de conversaciones para detectar:

- Respuestas incorrectas.
- Tono inadecuado.
- Oportunidades perdidas.
- Escalaciones tardías.
- Información desactualizada.
- Fricción en el usuario.

## 7. Expansión

Antes de crear nuevos agentes, validar:

- Que el primer agente tiene métricas estables.
- Que existe un nuevo caso de uso claro.
- Que el ecosistema puede soportarlo.
- Que la orquestación no se vuelve confusa.
- Que hay responsable de mantenimiento.
